# Contributing

Webspace is intended to become an interoperable medium, not a description of
one browser's current implementation.

## Before Proposing a Feature

Describe:

1. The creator or visitor problem being solved.
2. Why ordinary web platform capabilities are insufficient.
3. The security and privacy consequences.
4. How more than one browser could implement the behavior.
5. How older manifests and implementations should respond.
6. Whether the behavior belongs in the core standard or an optional
   capability.

Implementation experience is preferred before behavior becomes normative.

## Proposal Process

Substantial changes should begin as a GitHub issue. Once the problem and scope
are understood, a numbered Markdown proposal can be added under `proposals/`.
A proposal is exploratory unless it explicitly states otherwise.

No proposal becomes part of the standard merely by being merged. A future
governance document will define advancement stages, review requirements, and
conformance expectations.
